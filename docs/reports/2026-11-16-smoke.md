# 2026-11-16 本机冒烟测试

机器为 4 × NVIDIA H100 80GB HBM3，卡间 NVLink。隔离环境安装 SGLang 0.5.23、Transformers 5.19.0、PyTorch 2.14.1；模型为计划中的本地目录。测试服务使用 TP=4、BF16 权重、BF16 KV、262144 窗口和最多 4 个活跃请求。SGLang 启动日志确认权重加载完毕、KV cache 为 `torch.bfloat16`；首次启动经历内核编译。

- OpenAI Chat Completions：请求回复 hello，实际回复 `hello`。
- Anthropic Messages：工具选择返回 `calculator` 与 `{"expression":"2+3"}`；将工具结果 `5` 送回后，回复 `2 + 3 = 5`。流式请求观察到 message start、content block、message delta 和 message stop 事件。
- 长输入：使用 tokenizer 构造重复文本并提问，服务报告 `prompt_tokens=261020`、`completion_tokens=3`，回复 `42`。这验证接近 256K 上限的请求可以运行；重复输入不能证明长上下文代码任务质量，也未验证恰好达到 262144 总 tokens 的边界。
- 启动测试使用模型配置默认 recurrent state 精度。随后启动配置增加显式 `--mamba-ssm-dtype float32`，该新参数已通过 SGLang 0.5.23 参数帮助确认并通过配置单测，但上述运行实例没有使用显式参数重新启动。
- 单元测试：`python3 -m unittest discover -s tests -q`，4 项通过，包含本地模拟流式服务的并发测试。

## 并发性能冒烟

执行 `python3 -m petitcoding.benchmark --requests 8 --concurrency 1 2 4 --output-tokens 64 --warmup 1`。相同短 prompt、相同服务实例、带前缀缓存，thinking 开启；输出 token 由后端 usage 报告，包括 thinking。部分测试期间有其他 Anthropic 测试请求，因此结果仅用于确认工具工作，不适合作为基准比较或容量承诺。

| 并发 | 成功/请求 | 输出 tokens/s | TTFT p50 | 延迟 p50 |
| --- | --- | --- | --- | --- |
| 1 | 8/8 | 129.4 | 51 ms | 493 ms |
| 2 | 8/8 | 233.8 | 97 ms | 546 ms |
| 4 | 8/8 | 457.8 | 99 ms | 556 ms |

原始运行数据保存在本机临时目录 `/tmp/petitcoding-benchmark-steady/`，不会提交仓库。8 个样本不适合判断尾延迟；正式测试需隔离其他请求、分别测冷/热缓存、长上下文和更多样本。
